# Source Quality

## Tiering

1. Official documentation, standards, primary GitHub repos, source code.
2. Peer-reviewed papers, formal reports, vendor technical blogs with data.
3. Reputable journalism and analyst reports.
4. Practitioner blogs, forum posts, Reddit, social posts.

Use lower tiers for leads, anecdotes, or sentiment. Do not let them override primary sources.

## Recency

Use current sources for:

- pricing
- product features
- APIs and SDKs
- laws and regulations
- market or company claims
- security guidance

Include exact dates when the user uses relative terms like today, latest, or recent.

## Claim Hygiene

Every important claim needs:

- source link
- date or version if relevant
- confidence
- caveat if based on inference

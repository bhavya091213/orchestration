# Decision Gates

## Gate Checklist

Use a gate when any answer changes the shape of the work:

- what problem is being solved
- who the user is
- which model budget is acceptable
- whether to research before building
- whether to edit production paths
- whether to add dependencies
- whether to accept a risk

## Option Design

Good options are mutually exclusive and concrete:

- `Fast prototype`: lowest cost, highest rework risk.
- `Production-safe slice`: slower, testable, easier to merge.
- `Research first`: delays code, reduces domain risk.

Bad options are vague:

- `continue`
- `do more research`
- `make it better`

## Decision Log

Record decisions like this:

```markdown
Decision: [choice]
Reason: [why]
Tradeoff accepted: [cost/risk]
Date: [YYYY-MM-DD]
```

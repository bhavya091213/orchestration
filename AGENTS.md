# Repository guidance for coding agents

This repo is a **published mirror** of a live two-CLI agent configuration. It is not an
application: nothing here builds or runs in CI. The job when working in it is to keep the mirror
faithful, portable and free of machine-specific state.

## What mirrors what

| Repo path | Installs to | Notes |
| --- | --- | --- |
| `shared/` | `~/.agents/` | Single source of truth for both CLIs |
| `shared/skills/` | symlinked into `~/.claude/skills` **and** `~/.codex/skills` | One copy, two consumers |
| `claude-code/` | `~/.claude/` | Claude Code only |
| `codex/` | `~/.codex/` | Codex CLI only |
| `docs/` | nothing | Long-form guides for readers of the repo |

`install.sh` performs that mapping. If you add a new top-level directory or a new category of
file, update `install.sh` in the same change or it will silently not be installed.

## Skill placement rules

1. **A shared skill lives only in `shared/skills/`.** Never copy it into `claude-code/skills/` or
   `codex/skills/`. Duplication is the main way this repo rots, because the copies drift and
   nobody can tell which one the tool actually loaded.
2. **A skill only earns a platform-specific variant when its body genuinely differs per tool** -
   it references hooks, session-file layout, memory snapshots, slash-command syntax, or an
   installer that is tool-specific. When that happens, create *both* variants
   (`claude-code/skills/<name>/` and `codex/skills/<name>/`) so neither CLI is left without it,
   and keep the `name` identical across the pair.
3. If a variant pair converges back to identical content, collapse it into `shared/skills/` and
   move the old copies to `~/.agents/backups/`.
4. `claude-code/skills/learned/` is a deliberately empty landing directory for skills generated by
   `/learn`. Do not populate it in the repo.

## Rules must stay in sync

`shared/RULES.md` is authoritative.

- Claude Code imports it: `claude-code/CLAUDE.md` contains `@~/.agents/RULES.md` and nothing is
  duplicated.
- Codex cannot import, so `codex/AGENTS.md` carries a verbatim copy between:

  ```
  <!-- BEGIN SHARED RULES (synced from ~/.agents/RULES.md) -->
  <!-- END SHARED RULES -->
  ```

  After editing `shared/RULES.md`, regenerate that block (`~/.agents/bin/sync-agents rules`, or
  replace the block by hand) and commit both files together. Content outside the markers is
  hand-written Codex guidance and must be preserved.

## Never delete

**Never run `rm` / `rm -rf`, directly or via a subagent. Relocate with `mv` instead. If something
must be retired, `mv` it into a backup location (e.g. `~/.agents/backups/retired-<what>/`) and say
so in the report.**

Put that rule verbatim in every subagent brief that touches the filesystem.

## Never commit personal paths or secrets

This is a public repo. Two checks, both of which must come back clean:

```bash
# 1. No personal absolute home paths. Use ~ or $HOME instead.
grep -rnE '/(Users|home)/[^/ "]+' . --exclude-dir=.git

# 2. No credentials.
grep -rniE '(api[_-]?key|secret|token|password|bearer)[[:space:]]*[:=][[:space:]]*["'"'"'][A-Za-z0-9_\-]{16,}' . --exclude-dir=.git
```

Check 1 is expected to be **empty**. The only tolerable exception is an obviously fictional
placeholder inside sample output, and even there prefer `~/...`. Machine
state that Codex or Claude writes for itself - `[projects.*]` trust tables, `[hooks.state.*]`
hashes, the `notify` hook, local `node_repl` MCP entries - must be stripped from the example
config files, never copied between machines.

Credentials belong in the environment or the macOS Keychain (see `codex/scripts/codex-mcp-trello`
for the pattern), never in a tracked file.

## Frontmatter contract

Every `SKILL.md` needs at minimum:

```yaml
---
name: <kebab-case, matches the directory name>
description: <one sentence, includes the trigger conditions>
---
```

Agent files (`claude-code/agents/*.md`) need `name` and `description`; commands
(`claude-code/commands/*.md`) need a `description`. Codex roles (`codex/agents/*.toml`) must be
registered in `codex/config.example.toml` under `[agents.<name>]` with a `description` and a
`config_file` path, otherwise Codex will not see them.

## Verification checklist before publishing

```bash
# Every skill has name + description frontmatter
for f in shared/skills/*/SKILL.md claude-code/skills/*/SKILL.md codex/skills/*/SKILL.md; do
  grep -q '^name:' "$f" && grep -q '^description:' "$f" || echo "MISSING FRONTMATTER: $f"
done

# Every skill directory actually has a SKILL.md
for d in shared/skills/*/ codex/skills/*/; do [ -f "$d/SKILL.md" ] || echo "NO SKILL.md: $d"; done

# No personal home paths
grep -rnE '/(Users|home)/[^/ "]+' . --exclude-dir=.git

# Installer is syntactically valid and its plan is sane
bash -n install.sh
./install.sh --dry-run --all

# JSON validates
for f in shared/mcp-servers.json shared/skill-lock.json claude-code/settings.example.json \
         claude-code/hooks/hooks.json codex/hooks.json; do
  python3 -c "import json,sys;json.load(open(sys.argv[1]))" "$f" || echo "BAD JSON: $f"
done

# TOML validates
for f in codex/config.example.toml codex/agents/*.toml; do
  python3 -c "import tomllib,sys;tomllib.load(open(sys.argv[1],'rb'))" "$f" || echo "BAD TOML: $f"
done

# Counts still match what README.md claims
ls shared/skills | wc -l; ls claude-code/agents/*.md | wc -l; ls claude-code/commands/*.md | wc -l
```

If a count changes, update the README in the same commit. The README states exact numbers and a
stale number is a bug.

## Commit messages

```
<type>: <description>

<optional body>
```

`type` is one of `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `perf`, `ci`. Keep the
subject imperative and under ~72 characters. Group a rules change and its regenerated
`codex/AGENTS.md` block into one commit; group a skill addition and its README table row into one
commit.
